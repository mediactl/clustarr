# Live TV Phase B: the Live TV section in the ui — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Live TV" sidebar section in clustarr's ui with three of Dispatcharr's pages (Channels, M3U/EPG Manager, TV Guide) over the IPTVProvider and IPTVChannel resources and the tuner's objects, plus the one CRD addition the Manager needs (`spec.type: Xtream | M3U`).

**Architecture:** The manager's tuner writes what the pages read into the `clustarr-livetv` object store: a compact guide index beside the XEPG guide, and a processed copy of every active channel's logo. The ui reads IPTVProviders and IPTVChannels through its cache, reads the store through `Info` and `Get` (decoding an object again only when its digest moves), builds rows with pure functions in `ui/projection`, and renders three server-side pages swapped through htmx like the Library's. Every write is a `ui/actions` call: the Settings forms for both kinds, a merge patch per channel edit under the read `resourceVersion`, a create for "Add as channel", and the existing `clustarr.io/livetv-refresh` annotation for "Refresh now".

**Tech Stack:** Go 1.25, templ, htmx 2 with idiomorph and preload, shadcn-templ components, Tailwind (`make templ css`), controller-runtime's cache, JetStream object store (`pkg/events`), kubebuilder markers.

**Spec:** `docs/superpowers/specs/2026-10-27-livetv-direct-tuners-and-ui-design.md` §5.1-§5.7 (and §5.9, §7). Builds on Phase A (`docs/superpowers/plans/2026-10-27-livetv-direct-tuners.md`): `BlockStatus.URI` and `.Path` exist and every device lives at `/hdhr/<deviceID>`.

## Global Constraints

- The ui never writes status, and writes spec, metadata and Secrets only through `ui/actions` (`TestUINeverWrites`); `actions.Grants()`, `config/rbac/ui_role.yaml`, the chart's byte-for-byte copy in `charts/clustarr/templates/rbac.yaml` and `test/guards/ui_rbac_test.go`'s `uiActionGrants` are one set.
- `ui/actions` imports nothing from this module but `api/` and `pkg/obs/`.
- The ui's bus stays read-only: object-store `Info`, `Get` and `List` only.
- No browser request reaches a provider's image host (ADR-0011): a logo is the tuner's processed copy served by the ui from the store, else the channel's number on a tile.
- No page shows a credential or a provider's stream URL: the guide source reads as written (placeholders unexpanded) or `<server>/xmltv.php` without a query, and every stream URL the ui hands out is the tuner's `<block uri>/stream/<number>`.
- A page the Live TV sub-menu swaps answers `preloadable` (`Cache-Control: private, max-age=10`, `Vary: HX-Request`).
- The Plex look: tokens from `ui/static/input.css` (`bg-card`, `bg-muted/50`, `text-primary` for Plex Gold), 12px corners, glass from the `[data-slot=…]` rules; never edit a vendored component.
- After any `.templ` change run `make templ css` and commit the generated `_templ.go` files and `ui/static/app.css`.
- Gates (owner, 2026-10-08): `go build ./...`, `go vet` and `go test` of the touched packages without `KUBEBUILDER_ASSETS`, `make generate manifests` clean, `make brand-gate`, `helm lint --strict charts/clustarr`. Envtests are edited, named in the commit, and not run.

## Review Focus

1. **A provider whose objects are not there yet** (a new provider, a nil `LiveTV` store, a store that errors): every page renders with "not fetched yet" in place of the missing part and never answers 500. Pinned by Task 4's `TestANilStoreAnswersNothing` and Task 7's `TestGuideWithNoIndexSaysTheGuideIsNotBuiltYet`.
2. **The owner's 28,527-entry playlist** (16 MB of JSON for 53,000 entries): decoded once per digest, never per request, and paged and searched server-side. Pinned by Task 4's `TestTheStoreDecodesAnObjectOncePerDigest` and Task 6's `TestThePlaylistPanePagesAndSearchesServerSide`.
3. **Two edits of one channel at once** (a second tab, kubectl, Terraform): a patch carries the `resourceVersion` the page read, and a conflict is said in place, never written over. Pinned by Task 3's `TestEditChannelsSendsOneMergePatchPerChannelUnderItsResourceVersion` and Task 6's `TestAnEditThatLostARaceSaysSoInPlace`.
4. **The guide's edges and the viewer's clock**: a window outside the guide's seven days or a `from` that does not parse answers no blocks and no sentinel past an edge; a programme crossing a window boundary appears once, in the window it starts in; times are labelled in the browser's zone, never UTC text. Pinned by Task 7's `TestAProgrammeBelongsToTheWindowItStartsIn` and `TestGuideWindowClampsItsInputs`.
5. **Credentials and provider URLs leaking into a page**: pinned by Task 5's `TestSourcesPageNeverShowsTheAccount` and Task 6's `TestCopyStreamURLIsTheTunersNeverTheProviders`.

## Calls this plan makes (where it departs from the spec's letter)

- **Rows per page read, not in the projection round.** The Live TV kinds are a handful of objects that change on a minutes scale, so the handlers list them from the ui's cache as the Settings page and the root folders do, and the Manager's tables poll every 10 s as the dashboard's summary does (`hx-trigger="every 10s"`). The spec's "SSE fan-out for the live parts" is not built.
- **`Info` then `Get`, not an `objindex` watch.** Three objects per provider are read on page loads; a digest check per object at most every 5 s is enough.
- **The channel's edit dialog is the Settings form of the IPTVChannel kind** (every spec field, schema-driven), opened from the row with `?return=/livetv/channels`, as the Import Lists page opens its lists' forms.
- **Logos come from the store.** The tuner prefetches every active channel's resolved logo into the store (Task 2), so the ui can show it without a hot-link.
- **The guide grid is absolutely positioned** from the guide index's start, in 6-hour windows aligned to that start; a window is loaded by a sentinel with `hx-trigger="intersect once root:#guide-scroll"` (htmx's `revealed` watches the viewport, not an overflow container).
- **"Refresh now" is the `clustarr.io/livetv-refresh` annotation already built** (`app/livetv/controller/iptvprovider/config.go:42`, read into `tuner.Config.Refresh`); its constant moves to `api/` so `ui/actions` may name it.
