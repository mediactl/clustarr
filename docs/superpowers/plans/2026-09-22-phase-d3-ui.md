# Phase D3 — the first UI slice (M3)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** the pipeline and downloads pages render real cluster state, streamed, from a UI that still cannot write anything.

**Architecture:** `ui` gains a *read-only* informer-backed reader — a standalone controller-runtime `cache.Cache`, not a manager, because `ui` deliberately runs no manager and wants no metrics or leader-election port. One process-wide projection loop ticks the cache into `[]pipeline.Entry` and broadcasts to every open SSE connection, replacing the current per-connection poll. The never-writes invariant stops being an accident of "no RBAC grant exists" and becomes two guards.

**Spec:** `docs/superpowers/specs/2026-09-18-clustarr-design-amendment-1.md` §A3; scenario 14 at `docs/superpowers/plans/2026-09-18-remaining-work.md:1034-1038`. Scope: same file, line 897-898 — **the pipeline and downloads pages only.** Library, import lists, settings and unmatched are Phase G (line 927).

**Prior art that is verified, not assumed:** surveyed against source on 2026-09-22. Where this plan says a thing does not exist, it does not exist.

## Rulings made before implementation

**R1 — `ui` gets a standalone `cache.Cache`, not a manager.**
`cmd/clustarr/all.go:54-56` and `config/manager/ui.yaml:5-10` both record that `ui` runs no controller-runtime manager, so it offsets no metrics or health port. A manager would reintroduce both plus leader election, for a process that only reads. `cache.New` + `Start` in a goroutine + `WaitForCacheSync` gives informer-backed reads with none of that. Cost if wrong: a later phase that needs a manager re-wires `ui/run.go` once.

**R2 — readiness must stop being `/healthz`.**
`config/manager/ui.yaml:72-80` uses `/healthz` for both probes, with the comment that `ui` "has no external dependency yet". D3 gives it one. `/healthz` stays unconditional liveness; a new `/readyz` gates on cache sync, and `config/manager/ui.yaml` plus `charts/clustarr/templates/deployments.yaml` move the readinessProbe onto it. Shipping without this makes a UI whose caches never sync report Ready and serve empty pages forever.

**R3 — `ui`'s ClusterRole is hand-written, and `ui/` carries no `+kubebuilder:rbac` markers.**
Two reasons, and the second is the real one. Markers in `ui/` would merge into `clustarr-manager-role`, handing every controller the UI's grants. And a marker can only *add* verbs — there is no marker that expresses "and never write". The invariant is a property of the role document, so the role is a document, and D3-4 asserts it contains no write verb. `cmd/clustarr/rbac_markers_test.go`'s `RBAC_DIRS` guard stays satisfied because `ui/` keeps zero markers.

**R4 — the projection is process-wide, not per-connection.**
`ui/sse.go:36` polls `Entries` on a 5s ticker *inside each connection handler*, so N viewers re-project the whole catalogue N times. Projection means listing every catalog kind plus Downloads, Jobs, SubtitleRequests, Searches and MediaFiles, then indexing them by owner — the cost is real and it is per-tick. One loop computes it once and fans out. Cost if wrong: nothing; this is strictly less work than the skeleton does.

**R5 — the downloads page is built and tested now, and only its *e2e* waits on D2.**
`grabarr/` has `run.go` and nothing else: no controller, so nothing writes `Download.status.phase` and every row would sit at `phase: ""`. That blocks the *scenario*, not the page. Envtest writes status directly, so D3-2 and D3-3 get full coverage against hand-written status covering all 11 `DownloadPhase` values. Do not wait for D2 and do not stub grabarr.

**R6 — `Entry.Ref` is `types.NamespacedName`, and that is deliberate.**
`pkg/pipeline/project.go:40-48` records that the amendment specifies `commonv1.ObjectRef`, which does not exist in `api/common/v1alpha1`. Do not reintroduce it. Likewise `github.com/axadrn/shadcn-templ`, named in amendment §A3.1, is **not** in `go.mod` — D3 adds no dependency, so build components with plain templ and the CDN Tailwind already in `ui/views/layout.templ:35-37`.

**R7 — do not wire the NATS progress subjects.**
`pkg/events/subjects.go:319-327` defines `ProgressDownloadSubject` and `ProgressTranscodeSubject`; nothing publishes or subscribes to either. Sub-second progress needs a publisher in `grabarr`'s engine, which is D2's file and D2's field manager. Ticking the cache is correct for D3 and the two approaches compose later. Carry it forward rather than building half of it here.

**R8 — no browser-level test, and no new test dependency for one.**
Every UI assertion in the tree is `require.Contains` on the response body; `goquery` is present but belongs to `pkg/cardigann`. Keep substring assertions, but assert on stable `data-*` attributes rather than on visible copy, so a wording change does not fail a test and a markup change does.
